## 0. 総評

前回の削除 11 件のうち、**根拠に「利用 0」が混ざっていたのは 3 件**（お気に入り、Real/Fake 投票、共有 FB/LINE）。残り 8 件は「由来を読む・確かめる・書き足すに効くか」の設計判断で、告知の有無に関係しない。再判定の結果:

- **残す削除 8 件**、**別の形で実現 1 件**（お気に入り → ログイン不要の「棚」）、**条件付き復活（補強）1 件**（EN 切替）、**保留継続 1 件**（YouTube 検索）。
- ただし調査の過程で、告知前に直すべき **告知そのものを壊す欠陥を 3 つ**見つけた（§3）。削除の是非よりこちらが先。
  1. `images/og-default.png` が**文字なしの緑グラデーション 1 枚**（旧デザインの残骸）。トップ URL と写真なし品種 9 件（`wireframe/anthurium/*/index.html` のうち 9 スタブ）を X / LINE / Discord に貼ると、緑の長方形だけが出る。
  2. `supabase/functions/og-image` は**未デプロイ**（curl → `{"code":"NOT_FOUND"}`）。`share` 関数（`pages.js:685` の共有 URL）が写真なし品種で参照する画像は 404。デプロイしても中身は旧配色（紫 / 青 / 橙のピル、`sans-serif`、旧タグライン「品種の由来や歴史をコミュニティで収集・共有」）。
  3. 新着記録台帳のクエリが `.neq('type', 'seedling')` のまま（`app-core.js:2541-2544`。直上のコメントは「includes seedlings」、BOARD §4 は「実生も日付順で混ぜる」）。実生区画を撤去した代わりの受け皿が機能していない。

## 2. 特に検討を求められた 4 点

### 2-a. 「お気に入り」を「棚（Shelf）」として設計し直す

**結論: 価値あり。ただし「しおり」ではなく「自分の栽培株の棚」として、T28 標本ラベル印刷と同時に実装する。**

理由: 「あとで読む」はブラウザのブックマークで足りるが、「自分が持っている株」のリストはこのサイトにしか作れない。棚は次の 3 つに変換できる。
1. **ラベルの一括印刷**（T28）: 棚の 6 株を A4 1 枚に。会員特典の前段として「ログインなしで自分の分だけ」→ 稼働後「会員は全収録品種」に接続。
2. **写真提供の導線**: 棚の品種に図版がなければ「あなたの株の写真を提供 →」を棚ページに出す（`.sheet--plate` の再利用）。
3. **登録の導線**: 棚に入れたい品種が未収録なら、検索 0 件シートから「登録して棚に入れる」。

設計（Field Archive の語彙で）:
- 詳細ページ操作行（T27 の mono 1 行）に **「棚に入れる」/「棚にある」**（下線 1 本、アイコンなし）。
- 保存先は `localStorage['plants-story-shelf']`（`fullName` の配列）。ログイン不要。ログイン時は既存 `favorites` テーブルへ同期（テーブルは残置済み、`pages.js:562-` の `toggleFavorite` を流用）。
- 入口は **フッターと mobile-nav の末尾に「棚（3）」**、件数 0 のときは非表示。ヘッダーには置かない（6 要素を守る）。
- `/shelf` ページ: 見出し「あなたの棚」+ mono「この端末に保存 · ログインで引き継ぎ」、本文は `.ledger-table`（新着記録と同じ部品）、行末に「外す」。下に **「棚のラベルを印刷 →」**（T28 の dialog を複数品種で開く）。空のときは `.sheet`「棚は空です。品種ページの『棚に入れる』から。」
- 見た目の原則: ☆・ハート・カウンター・トースト演出なし。押した直後に文字が「棚にある」に変わるだけ。

コスト: 2.5〜3h（`archive.js` に shelf モジュール ~120 行、`index.html` に `#page-shelf` 1 区画、`app-core.js simplePages` に `shelf`、i18n 6 キー、T28 dialog に複数品種対応 +30 分）。**T28 と同じプレビューで確認**。

### 2-b. 「このサイトに参加できる」と分かる装置は十分か

現状の参加装置（コードで確認）: ヘッダー「+ 投稿」（PC のみ表示、`components.css:2783` で 767px 以下は `.header__nav` 非表示）／mobile-nav 2 番目「品種を投稿」／コロフォン CTA「あなたの交配を系統図に残す →」／検索 0 件 `.sheet--search`／系統図の未収録親「登録する →」／詳細ページの「画像追加」ボタン。

判定: **PC は十分。スマホは不足。** Instagram から来るのはスマホで、着地は品種詳細。そこで見えるのは h1 の下のボタン列（シェア・編集・画像追加・削除依頼）で、「記録を足せる」ことが読めない。ヘッダーの「+ 投稿」はハンバーガーの中。

修正案（2 つ、いずれも小さい）:
1. **375px のヘッダーに「+ 投稿」を出し、「ログイン」をハンバーガーへ**（30 分、CSS + HTML 数行）。ログインは手段、投稿は目的。幅の計算: ロゴ 0.95rem「AROID ORIGINS」≈130px + 「+ 投稿」≈64px + ハンバーガー 44px = 約 240px / 343px で収まる。プロフィールボタンはログイン後のみなので影響なし。
2. **詳細ページの標本ラベル直下に mono 1 行**「この台紙に書き足す — 写真 · 由来記録 · 訂正」（T27 の操作行そのもの。前倒しは不要、T27 で解決）。加えて、フォーム冒頭の「投稿者名は人物索引と系統図に載ります」（BOARD §4 の報酬明記）を T27 の範囲に含める。

### 2-c. スマホ着地の最初の 1 画面と告知用 OGP

**masthead（375px）の実測見込み**: header 56 + kicker 36 + タイトル 2 行（16vw ≈ 60px × 0.92 × 2）≈ 126 + タグライン 34 + 定義文 2 行 ≈ 50 + 検索バー 72 = 約 374px。iPhone SE（667px）でも定義文と検索まで初回画面に入る。**位置は合格、重みが不足**: 定義文 `.masthead__desc` は `--color-mid` の 0.875rem、タグライン「一葉に、千の物語。」がその上に 1.35rem セリフで載る。初見の人が先に読むのは大きいほうで、それはサイトの説明になっていない。

修正案（CSS 2 行 + プレビュー確認）:
```css
.masthead__desc { color: var(--color-ink); font-size: 1rem; max-width: 30em; }
.masthead__tagline { font-size: 1.05rem; color: var(--color-mid); font-weight: 600; }
```
順序は変えない（タイトル → 一葉に、千の物語。→ 定義文）。定義文がインク色で立ち、タグラインは添え書きに下がる。

**OGP（告知の顔）**: §0 のとおり現状は緑の無地。設計:
- `images/og-default.png`（1200×630、静的 1 枚）: 紙 `#F4F1EA` の地、外周 8px と内側 20px の**二重罫**（T28 ラベルと同じ構造）、左上 mono `AROID ORIGINS · plantsstory.com`、中央に Shippori Mincho で「誰が、いつ、どこで名付けたか」、その下 1 行小さく「アロイドの由来を出典つきで記録する図鑑」、右下 mono `ANTHURIUM · 31 ENTRIES · 2026`。色はインク 1 色 + 年号の黄土のみ。**植物イラストは入れない**（AI 図版 NG。オーナー写真の版画変換が届いたら右 1/3 に差し替え可）。
- 品種ページ用「標本ラベル OG」: 同じ台紙に `Anthurium` イタリック + 品種名、cite 行（記載者 · 年 · 産地 / 作出者 · 年）、右下 `NO. 013`。写真がある品種は現状どおり写真を優先（写真のほうが Instagram では強い）。
- 実装: **静的スタブ生成スクリプトの中で PNG を焼く**（`scripts/` の既存ジェネレータに `@resvg/resvg-js` + 同梱フォント `scripts/fonts/{CormorantGaramond,ShipporiMincho,IBMPlexMono}.ttf` を追加、`images/og/<slug>.png` に出力、スタブと `share` 関数の fallback を同 URL に）。Edge Function `og-image` は**削除**（未デプロイ・旧配色・`sans-serif` で日本語が豆腐になる可能性）。コスト 3〜4h。同じ描画関数を T29「今日の一葉 OGP」と T28 ラベルの画面プレビューに使い回せる。
- 告知投稿のテキストは定義文 + URL のみ。ハッシュタグは `#Anthurium #アンスリウム` の 2 つまで（サイトの無装飾と揃える）。

### 2-d. EN 切替をフッターに置いて英語圏を逃さないか

- **逃さない**: `forms.js:270` で `navigator.language` が `en*` なら初回から英語。`document.documentElement.lang` も切替（`forms.js:300`）。判定結果は `localStorage['plants-story-lang']` に保存され、次回も維持。
- 残る穴は「英語 OS ではないが英語で読みたい人」（例: 台湾・タイ・韓国のアロイド愛好家。`navigator.language` が `zh` `th` `ko` のときは `jp` に落ちる: `forms.js:270` の三項演算子）。**修正: 既定を「`ja*` なら jp、それ以外は en」に反転**（1 行）。日本語話者は `ja` を必ず持つので日本人に不利益はない。これが最も効く 1 行。
- 補強として §1-10 の masthead mono リンク。hreflang は凍結（被リンク月 10 件超で再検討）どおり。初回だけの案内バナー・自動リダイレクト・言語選択モーダルは**不採用**（初見の 1 画面を汚す）。

1. **OG 画像の確認（5 分）**: 標本台紙 OG（デフォルト 1 枚）をプレビューで見て可否。文言は定義文そのまま。
