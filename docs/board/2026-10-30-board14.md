# 第14回 常設ボード（2026-10-30）「わかりやすく、続けて使いたくなる管理と検索」

オーナー原文: 「各部門で会議をして追加要素や削除する要素などを出してどうしていくか決めて実行までして。このサイトはスマホで30～60代が中心で使うと予想されています。わかりやすく、便利に継続的に使いたくなるような管理、検索できるような形にしなければならない。」

出席: デザイン（design-director）・集客（content-strategist）・分類（taxonomy-editor）・収益（monetization-lead）、統括（product-owner）。実装は Claude Code が同日に行った。

## 1. 各部門の報告（要約）

### デザイン
- 「調べる」の検索欄が結果を出していなかった。Enter は `navigateTo('search')` を呼ぶが、検索は `_fromRoute` 付きのときしか走らない。
- 検索欄には「人名・産地」と書いてあるのに、名前と別名しか探していなかった。
- 同じ画面の名前が 4 通りあった（自分の株／マイプランツ／自分の記録）。
- 押せる面は 44px、ラベルは 12px で、30〜60 代には小さい。
- 自分の株には並べ替えも次の一手もなく、事務的な行（実生の枠・CSV・会員メール）が株を押し下げていた。
- 足す提案: 入力途中の候補、0 件のときの案内、自分の株の「次にやること」と絞り込み、最近見た品種。

### 集客
- 人名・国名・交配親では 0 件になる（例: Croat、ペルー、ドラヤキ）。
- 「クイーンアンスリウム」で検索すると 'Queen of Hearts' に案内されていた。
- お気に入りのコードは、ボタンがどこにもなく使われていなかった。
- 再訪の動機として、最近見た品種と記録の振り返りを提案。
- 季節の手入れ通知は「育て方は書かない」決定と衝突するので作らない。

### 分類
- 原種の行は 32 件で、調べるページの 38 とずれていた。
- 検索の照合で、×・var. の表記ゆれを吸収していなかった。
- kana 列の追加と、危ない別名 2 件の削除を提案。
- 用語の 1 行説明、作出者リンクの飛び先、「採取」→「採集」を提案。

### 収益
- 継続率を 25→50%、ログイン率を 4→6% に上げると、月 約1,600円 → 3,900円（推定）。継続は掛け算の倍率で、土台は来訪数。
- 呼び名の統一、事務的な行を減らすこと、自分の株の絞り込み、OFUSE の文字リンク（スイッチ off）を提案。
- やらない: 全画面の寄付案内・浮動ボタン・寄付の特典。

## 2. 裁定（統括）

- **呼び名は「自分の株」に統一する。** 第13回の「マイプランツ」は上書きする。
- **OFUSE は第8回の却下を上書きし、文字リンクだけで採用する。** 理由は、カード決済が 2027-02 以降に延びたこと。
- **kana 列は、表示しない（第11回のオーナー指示）。列そのものは保留する。**
- **却下:** 自分の株への道具の PR、季節の通知、URL 読み替え処理（archive.js）の変更。URL 読み替えは親を結ぶ処理ではなかった。
- 便1 = T171〜T178、便2 = T179〜T186、便3 = T187・T188・T130・T131・T189。
