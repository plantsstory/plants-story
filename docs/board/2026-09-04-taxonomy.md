# 分類・命名編集長レポート（2026-09-04）

担当: taxonomy-editor（常設ボード）
対象: Aroid Origins (https://plantsstory.com) — `cultivars` 全69件（Anthurium 31 / Monstera 10 / Philodendron 9 / Platycerium 19）、`wireframe/js/forms.js`・`pages.js`・`app-core.js`、`supabase/functions/research-origin/index.ts`、`wireframe/index.html` の `page-contribute` / `page-guide`。

## 0. 要旨

- 4区分（原種 / Hybrid / Clone / Seedling）は維持してよい。ただし現行の判定基準は「入力者の感覚」に依存しており、同じ名前が個体（Clone）にも実生群（Hybrid）にも使われる流通実態（'Mystique a88'、'Red crystallinum'、'King of Spades'）に対応できていない。**「その名前を名乗る株が、1個体の栄養繁殖由来だけか／複数の遺伝的に異なる個体を含むか」**を唯一の判定軸として明文化する。
- 追加区分は不要。sp./aff./cf./ssp./var. は **原種の修飾子（qualifier）カラム**、斑入り・産地フォーム・流通名・TC由来・系統(line) は **タグ**で表す。区分を増やすと投稿者が迷い、データが割れる。
- 表記は ICNCP（栽培植物命名規約）に揃える: 属名・種小名はイタリック、栽培品種名は **半角シングルクォート + 各語頭大文字**、交配式は `母親 × 父親`（× は U+00D7、前後に半角スペース）、非公式名（産地・未確立の流通名）は **ダブルクォート**。
- 既存データの修正は 69件中 **28件**（名前の表記ゆれ 9件、区分の見直し 6件、由来テキストの品質違反 10件、構造データ不整合 8件、重複含む）。うち名前の機械的修正は即実施可能、区分見直し 5件はオーナー判断が必要。
- 検証した外部基準: ICNCP（cultivar の定義 Art. 2.3、× の使い方、ダブルクォート禁止）、IAS Aroid Cultivar Registry（Araceae の ICRA。登録票は Cultivar Type: Hybrid、Seed Parent / Pollen Parent、Originator / Namer を分けて記録）、Jay Vannini "Velvet leaf anthuriums in cultivation"（sp. nov. / sp. ined. / aff. / cf. の使い分け、産地エコタイプ表記、'Dark Mama' の綴り変遷）、NSE Tropicals・Carnivero 等の商品ページ。

## 1. 定義集（「使い方」ページにそのまま掲載できる文章）

> 以下は `wireframe/index.html` の `page-guide` セクション「品種タイプの違い」の差し替え候補です。`translations.json` の `type_species` / `type_hybrid` / `type_clone` / `type_seedling` およびフォームの `type-hint` も同文に揃えてください。

### 1.0 まず1つだけ確認してください（判定フローチャート）

```
その名前は、学術的に発表された学名（属名 + 種小名）ですか？
  └ はい、または sp./aff./cf. 付きの未同定株 ……………………………… → 原種（Species）
  └ いいえ（'クォート' 付きの園芸名・流通名）
       その名前を名乗る株は「1個体を株分け・組織培養で増やしたもの」だけですか？
         └ はい（種から育てた別個体は同じ名前を名乗れない）…………… → クローン（Clone）
         └ いいえ（同じ交配式の実生兄弟がまとめてその名前で流通）…… → ハイブリッド（Hybrid）
       名前がまだ無く、自分が播いた実生の記録として登録したい …………… → 実生（Seedling）
```

迷ったら **「その名前の株を種から増やしても同じ名前で売られているか」** を思い出してください。売られていれば Hybrid、売られていなければ Clone です。

### 1.1 原種（Species）

**定義**: 自然界に存在する種、およびその種と考えられる株です。学術的に記載され学名が付いた種（例: *Anthurium crystallinum*）のほか、まだ記載されていない未同定株（sp.）、既知種に近縁だが別種と思われる株（aff.）、既知種と思われるが確定できない株（cf.）、亜種・変種（ssp. / var.）を含みます。人が交配して作った株は、たとえ親が同じ種どうし（例: carlablackiae × carlablackiae）でも原種ではありません。

**名前の書き方**: 属名 + 種小名（`Anthurium crystallinum`）。未同定は `Anthurium sp. "Peru"` のように sp. の後に産地や入手元を **ダブルクォート** で添えます。sp./aff./cf. の後には必ず半角スペースを入れます。

**判定例**
1. `Anthurium crystallinum` → **原種**。IPNI/POWO に記載あり（Linden & André, 1873）。
2. `Anthurium aff. besseae`（パナマ Darién 産、besseae とは別物と考えられる株）→ **原種（aff.）**。名前は推測せず aff. のまま登録します。
3. `Philodendron 'El Choco Red'` → **原種**。2020年代に *Philodendron rubrijuvenile* として記載されました。登録名は `Philodendron rubrijuvenile`、'El Choco Red' は「流通名」タグに移します。
4. （反例）`Monstera obliqua 'Peru'` → 原種 *Monstera obliqua* の **産地フォーム**。クローン名ではないので `Monstera obliqua "Peru"`（原種 + 産地タグ）で登録します。

### 1.2 ハイブリッド（Hybrid）

**定義**: 特定の交配式（母親 × 父親）から得られた **実生群** に付けられた名前です。同じ名前を名乗る株が複数あり、それぞれ遺伝的に異なります（兄弟株）。交配者が F1 を選抜して名前を付け、その後も同じ交配を繰り返して同じ名前で流通させる場合はこちらです。ICNCP では厳密には cultivar ではなく「grex（交配群）」に近い概念ですが、アロイドの流通では名前付きハイブリッドとして扱われます。

**名前の書き方**: 属名 + 'ハイブリッド名'（`Anthurium 'Mystique A88'`）。交配式は必須で、親は既存の品種ページにリンクします。親が不明・複雑な場合は「交配式不明 / 複数世代の複合交配」を選べます。

**判定例**
1. `Anthurium 'Mystique A88'`（'Dorayaki' × 'Red Crystallinum' NSE、Mr. Chandra 作出）→ **Hybrid**。オリジナル個体はあるが、流通しているのは同じ交配式の F1 兄弟株。
2. `Philodendron 'Glorious'`（*P. gloriosum* × *P. melanochrysum*、Keith Henderson 1975）→ **Hybrid**。IAS 登録簿でも Cultivar Type: Hybrid。種子・組織培養の両方で大量流通しており、1個体に限定されない。
3. `Anthurium 'Red Crystallinum'`（NSE）→ **Hybrid**。Tim Anderson の 'Wonderboy' 系統に由来し、NSE / Tezula / Docblock で別個体から実生化された複数系統の総称。
4. （反例）`Anthurium 'Dark Mama' × papillilaminum` → 名前が付いていない交配式そのものは Hybrid の登録対象ではなく、**Seedling**（自分の播種記録）として登録します。

### 1.3 クローン（Clone）

**定義**: **たった1個体** に付けられた名前です。その名前を名乗ってよいのは、その個体を株分け・挿し木・組織培養（TC）で増やした株だけです。交配親が判明していても（例: 'Dark Mama' = *warocqueanum* × *papillilaminum*）、名前が「その交配の全兄弟」ではなく「選抜された1株とそのコピー」を指すならクローンです。原種の中から選ばれた特別な個体（斑入り、暗色個体）や、組織培養で生じた変異個体もクローンです。

**名前の書き方**: 属名 [+ 種小名] + 'クローン名'。単一の原種に由来する場合は種小名を必ず含めます（`Monstera deliciosa 'Thai Constellation'`、`Philodendron erubescens 'Pink Princess'`）。種間交配や親不明の場合は属名 + 'クローン名'（`Anthurium 'Ace of Spades'`）。

**判定例**
1. `Anthurium 'Dark Mama'` → **Clone**。NSE Tropicals も「母株からの offset / clone」として販売。'Dark Mama' の自家受粉実生は 'Dark Mama' ではなく「'Dark Mama' self（Seedling）」です。
2. `Anthurium 'Ace of Spades'` → **Clone**。Silver Krome Gardens の Denis Rotolante が未同定株（当初 *A. hoffmannii* ラベル）の実生から1株を選抜し命名。交配式は不明で構いません。
3. `Monstera deliciosa 'Thai Constellation'` → **Clone**。タイの組織培養ラボで生じた斑入り変異個体を TC で増殖。
4. （境界例）`Anthurium 'King of Spades'` → 現在 Clone 登録ですが、由来文に「original から代々実生をして改良、その一部が出回っている」とある。流通株が実生なら **Hybrid（系統）** に該当します（→ 6. 確認事項）。

### 1.4 実生（Seedling）

**定義**: 趣味家が自分で交配・播種した株の **記録** です。名前はまだ無く、交配式と播種日、親株の写真で識別します。将来その中の1株に名前を付けて栄養繁殖で配布するなら、その時点で **Clone** として新規登録し、実生記録からリンクします。実生群全体に名前を付けて同じ交配を繰り返し流通させるなら **Hybrid** です。

**名前の書き方**: 属名 + 交配式（`Anthurium forgetii × 'Titanium'`）。クォートで交配式全体を囲まないでください。自分の管理番号（HR1, #3 など）はダブルクォートで添えます（`Anthurium carlablackiae "HR1" × carlablackiae "HR2"`）。

**判定例**
1. `Anthurium carlablackiae "HR1" × carlablackiae "HR2"`（@hare_anthurium、2025-11-10 播種）→ **Seedling**。同種どうしの交配でも原種ではありません。
2. `Anthurium forgetii × 'Titanium'` → **Seedling**。'Titanium' は（aff. besseae × nigrolaminum）の名前付き Hybrid なので、親としてリンク可能。
3. 上記実生から1株を選抜して 'Hare Black' と命名し株分けで配布 → **Clone** として新規登録（実生記録を「選抜元」としてリンク）。
4. （反例）ナーセリーが同じ交配を毎年繰り返し 'Galaxy' の名で販売 → **Hybrid**。

## 2. 区分・タグの変更提案（DB / UI / 移行）

### 2.1 区分は 4 値のまま。追加しない理由
- sp./aff./cf. は「同定の確度」であって「由来の種類」ではない。原種の下位修飾子として保持すれば十分（現在は `origins[].structured.species_subcategory` に埋もれており、バッジは名前の正規表現 `getSpeciesBadgeText` で二重管理されている）。
- 斑入り（variegata）は原種にも Clone にも Hybrid にも起こる直交属性 → タグ。
- 産地フォーム（"Peru"、"Colombia form"）は原種の下位情報 → 原種 + `locality` フィールド。Vannini も「Río Guanche ecotype」等を種名の後の記述子として扱っている。
- 流通名（trade name）は名前の **状態** であって区分ではない → `name_status`。

### 2.2 スキーマ変更案（`cultivars` テーブル）

| カラム | 型 | 用途 | 既存データからの導出 |
|---|---|---|---|
| `species_qualifier` | enum `none / sp / aff / cf / ssp / var / f` | 原種の修飾子。バッジ表示はこのカラムから | 名前の `\b(sp|aff|cf)\b` と `structured.species_subcategory` から一括移行 |
| `species_epithet` | text | 種小名（原種は必須、Clone は単一種由来なら必須） | 名前の第2語（小文字ラテン語）を抽出 |
| `cultivar_epithet` | text | 'クォート' 内の名前のみ | 名前から `'…'` を抽出 |
| `display_name` | text (generated / view) | `genus + epithet + qualifier + 'cultivar'` を正規化して生成。`cultivar_name` は検索キーとして残す | — |
| `name_status` | enum `accepted / informal / trade / disputed` | accepted = 学名確定または IAS 登録済、informal = sp./産地/個人管理番号、trade = 流通名（正式名あり）、disputed = 親・作出者に異説 | 手動 |
| `locality` | text | 産地フォーム（"Peru"、"Darién"）。未同定株と産地フォームで使用 | 名前・`known_habitats` から手動 |
| `aliases` | text[] | 旧綴り・同物異名（'Dark Momma'、debilis、angolense、'El Choco Red'） | 括弧書き `(…)` から抽出 |
| `tags` | text[] | `variegata`, `locality_form`, `tc_origin`, `line`（複数系統の総称）, `selfed`, `disputed_parentage` | 手動 |
| `parent_a_id` / `parent_b_id` | uuid FK → cultivars | 交配式の親リンク（母 / 父） | 既存 `formula.parentA/B` の文字列を名寄せして紐付け |
| `parent_a_text` / `parent_b_text` | text | 未登録の親の自由記述（FK が NULL のとき表示） | `formula.parentA/B` をそのまま |
| `formula_status` | enum `known / partial / unknown / complex` | Hybrid でも「不明」「複合交配」を許容する | Hybrid で formula 空 → unknown |
| `propagation` | enum `vegetative / seed / tc / mixed` | Clone の根拠（vegetative / tc）、Hybrid は seed | 区分から既定値 |
| `selected_from_id` | uuid FK → cultivars | Seedling → Clone 昇格時のリンク | — |

`origins[].structured.origin_type` は `cultivars.type` と重複しており、現に 2 件で食い違っている（→ 5.）。**`structured.origin_type` を廃止し、表示は `cultivars.type` を参照**する（`renderStructuredOrigin` の冒頭バッジは `getBadgeInfo(row.type, …)` に変更）。

### 2.3 UI 変更
- **投稿フォーム** (`page-contribute`):
  - 「品種名」を 1 つの自由入力から **属（select） / 種小名（text, 原種・単一種由来 Clone で必須） / 修飾子（chips: なし・sp.・aff.・cf.・ssp.・var.） / 品種名（'…' 不要、Clone/Hybrid で必須） / 産地・管理番号（任意）** に分割し、プレビューで正規化表記を表示する。`genus + " '" + name + "' [Seedling]"`（forms.js:1274）のように交配式全体をクォートで包む合成をやめる。
  - Hybrid の交配式は「既存品種から選ぶ（オートコンプリート）」を第一候補にし、無ければ自由記述。母 × 父の順を明記（現在 Clone フォームの placeholder だけ「Parent A / Parent B」で母父の表示が無い）。
  - Hybrid の交配式必須は維持するが「不明 / 複合交配」チェックを追加（'Red Crystallinum' のような系統を登録できない）。
  - タイプ選択の `?` ヒントを 1. の定義文に差し替え。特に Hybrid の現行文「交配式につく品種名（…F1の不特定多数の選抜個体につく名前）」は正しいが、Clone の「self や F 個体等の画像掲載可能」は誤解を招く（self 実生は Clone ではない）。
- **バッジ**: `getSpeciesBadgeText` の正規表現判定を `species_qualifier` 参照に置き換え。`sp.` バッジは「未同定」、`aff.`「近縁未同定」、`cf.`「要確認」のツールチップを付ける。
- **詳細ページ**: 「系統」ブロックを新設し、親（リンク）→ 本品種 → この品種を親にもつ品種（逆引き）を表示。`name_status = trade` のときは正式名を主表示、流通名を副表示。

### 2.4 移行手順
1. `ALTER TABLE cultivars ADD COLUMN …`（上表）。すべて NULL 許容で追加し、既存の `cultivar_name` は触らない。
2. 一括スクリプト（node / SQL）で `species_qualifier`, `species_epithet`, `cultivar_epithet`, `aliases` を名前から導出。導出結果を CSV でオーナー確認 → 適用。
3. 5. の修正リストに従い `cultivar_name` を正規化（`slug` / OGP 関数・`[Seedling]` サフィックスに依存する箇所 `pages.js:75,703,766…` を先に `display_name` 参照へ変更）。
4. `origins[].structured.origin_type` を読まないようフロントを変更してから、JSON から当該キーを削除。
5. AI 調査関数 `research-origin/index.ts` の出力スキーマに `formula_status`, `name_status` を追加し、「サイズ・生育習性の描写を書かない」「不明は `null`（文字列 "null" / "不明" を返さない）」をプロンプトに明記（現状 `author_name: "null"` が保存されている）。

## 3. グループ分けとナビの提案（画面ごと）

### 3.1 属ページ（一覧）
- 既定並び: **区分グループ順 → 名前順**。原種 → Hybrid → Clone（Seedling は現行どおり別タブ）。初心者は「まず本物の種を知り、次にそこから作られたもの」を辿るのが最も理解しやすく、コレクターは区分チップで即絞り込める。
- 原種グループ内の順序: 記載種（アルファベット順）→ ssp./var. → cf. → aff. → sp.（未同定は末尾）。
- フィルタチップは現行 3 種（原種 / Hybrid / Clone）に加え、タグチップ **「斑入り」「産地フォーム」** を追加。産地別や見た目（ビロード葉）グループは「タグ」で任意に絞れる形にとどめ、既定の並びにはしない（分類軸が混ざると迷う）。
- 一覧カードの名前表示: 属名イタリック + 種小名イタリック + 修飾子ローマン + 'クローン名' ローマン。`name_status = trade` は流通名を灰色で併記。

### 3.2 品種詳細ページ
1. 見出し: 正規化表記 + 区分バッジ + 修飾子バッジ + タグ。
2. **系統ブロック**（Hybrid / Clone / Seedling）: 母 × 父（リンク）、作出者、命名者、命名年、`formula_status`。異説がある場合は「異説あり」バッジと両説の出典。
3. 由来記録（既存）。
4. **派生品種**: この品種を親・選抜元とする品種の一覧（逆引き）。'Dark Mama' → 'Fat Mama' 等が自然に繋がる。
5. 画像ギャラリー。

### 3.3 投稿フォーム
- タイプ選択を最上部に移し、選択に応じて名前入力欄の構成を変える（原種: 属+種小名+修飾子 / Hybrid・Clone: 属+[種小名]+品種名 / Seedling: 属+交配式）。
- 判定フローチャート（1.0）をタイプ選択の下にアコーディオンで表示。

### 3.4 使い方ガイド
- 「品種タイプの違い」を 1. の定義集に差し替え、各区分に判定例 3 つ + 反例 1 つ。
- 「表記ルール」節（4.）を新設。

## 4. 表記ルール

| 項目 | ルール | 例 |
|---|---|---|
| 属名・種小名 | イタリック。属名は大文字始まり、種小名は常に小文字 | *Anthurium crystallinum* |
| 修飾子 sp./aff./cf./ssp./var. | ローマン（非イタリック）、後ろに半角スペース | *Anthurium* aff. *besseae* / *Anthurium* sp. "Peru" |
| 未同定株の識別子 | sp. の後にダブルクォートで産地・入手元 | *Anthurium* sp. "Peru" |
| 栽培品種名（Clone / Hybrid） | 半角シングルクォート、各語頭大文字、ローマン。ダブルクォートは ICNCP で禁止 | *Anthurium* 'Dark Mama' / 'Mystique A88' |
| 単一種由来の Clone | 種小名を必ず含める（オーナー既定ルール） | *Monstera deliciosa* 'Thai Constellation' |
| 種間交配・親不明の Clone / Hybrid | 属名 + '名前' | *Anthurium* 'Ace of Spades' |
| 交配式 | `母親 × 父親`。× は U+00D7（x や X は不可）、前後に半角スペース。母親を先に書く（ICNCP は ♀ 先頭または alphabetical を許容。本サイトは母親先頭で固定） | *Philodendron verrucosum* × *P. melanochrysum* |
| 交配式中の属名 | 2 回目以降は頭文字省略可 | *A. warocqueanum* × *A. papillilaminum* |
| 個人の管理番号・非公式名 | ダブルクォート（cultivar 名と区別） | *A. carlablackiae* "HR1" |
| 流通名（正式名あり） | 正式名を主、流通名を副表示（`name_status = trade`） | *Philodendron rubrijuvenile*（流通名 'El Choco Red'） |
| 系統・出所の付記 | 品種名の外に括弧で | *Anthurium* 'Red Crystallinum' (NSE) |
| 同物異名・旧綴り | 名前に括弧で書かず `aliases` に格納 | debilis, angolense, 'Dark Momma' |

## 6. オーナーへの確認事項

1. **「品種名には必ず種小名を含める」ルールの適用範囲**: 種間交配や親不明の Clone/Hybrid（'Ace of Spades', 'Dark Mama', 'Galaxy'）には物理的に種小名を付けられません。「単一の原種に由来する品種のみ必須」という解釈でよいですか。
2. **'King of Spades' (id 2)**: 流通株が代々の実生なら Hybrid（系統）へ変更しますか。それともオリジナル個体の名前として Clone を維持しますか。
3. **Philodendron 'Glorious' / 'Splendid' / 'Majestic'**: 種子・TC で大量流通する古典的交配種です。IAS 登録簿では Cultivar Type: Hybrid。本サイトの定義（複数個体が同名 = Hybrid）に従い Hybrid へ変更してよいですか（現在は Clone）。
4. **'Dark Mama' の親と作出者**: NSE（*warocqueanum* × *papillilaminum*、Karel Havlicek）と Vannini（John Banta 起源、'Dark Momma'）が食い違い、ボードの前提情報（*crystallinum* × *papillilaminum*）とも異なります。「異説あり」として両論併記でよいですか。特定の説を採用する根拠（一次資料）があれば教えてください。
5. **未同定株の識別子の書式**: `Anthurium sp. "Peru"`（ダブルクォート）を推奨しますが、流通で多い `Anthurium sp. Peru`（クォートなし）にしますか。いずれにせよシングルクォートは避けます。
6. **Seedling から Clone への昇格**: 実生記録の 1 株に名前を付けたとき、(a) 新規 Clone を登録して実生記録にリンク、(b) 実生記録自体の type を書き換え、のどちらにしますか（推奨 a）。
7. **'Albo Variegata' / 'Aurea' のような「同名の複数変異」**: Clone のまま「総称」タグで扱いますか、Hybrid 側の `line` 扱いにしますか。
8. **Platycerium**: アロイドではありませんが 19 件あります。非公開のまま維持するなら分類ルールは同じでよいですか（sp./aff. の扱いはシダでも同一）。
9. **和名併記**: `japanese_name` カラムを新設し一覧・詳細で併記しますか。現在はカラム自体がありません。
