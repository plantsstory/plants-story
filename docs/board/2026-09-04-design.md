## 0. 総評

`archive.css` が効いている画面（トップの masthead / ledger / story / index / timeline / ledger-table、詳細の specimen / related、affiliate、footer）は「紙・インク・罫線」の系で揃っており良い。問題は **archive.css の下に眠っている旧「Tropical Shade」層**で、次の 6 種類が各所に残っている。

| 種類 | 残っている場所（代表） |
|---|---|
| 絵文字アイコン | モバイルナビ、詳細ページの操作ボタン列、属タブ、検索ボタン🔍、由来カードのフッター/出典、`🚩 削除依頼`、`📤 投稿する`、`🤖 AI調査中`、ガイド見出し |
| グラデーション | `.gallery__empty`（外枠）、`.recent-card__img`（お気に入りのフォールバック）、`.gallery__img`、`.contact-link__icon--instagram`、`.about-mission`（ink 一色に置換済だが重い） |
| 影・浮き上がり | `.pricing-card:hover`、`.contact-link:hover`、`.fav-remove-btn`、`.ai-researching::after`、`dialog.parent-photo-dialog img` |
| パステル/彩度の高いバッジ | `.tier-badge`（紫・青・緑・橙・赤の 5 色）、`.vote-btn--active`(#e8f5e9) / `--active-down`(#fce4ec)、`.profile-sub-badge`、`.pricing-card--recommended`、`.badge--research`、admin の `.badge-*` |
| 汎用カードグリッド | お気に入り / 投稿履歴 / プロフィールの `.card-grid`、実生ノートの `.grid--3`、投稿フォームの 3 枚の `.card`、ガイドの 4 枚の `.card`、お問い合わせ |
| 旧パレットの生 HEX | `#1B4332`（favicon / theme-color / manifest）、`#2D6A4F`（プレースホルダ SVG）、`#dc3545`（削除ボタン inline）、`#c0392b`（決済エラー）、`#8ecfff`（ギャラリーオーバーレイのリンク） |

加えて **モバイル 375px でタップ領域 44px を割る要素が多い**（`archive.css` 自身が `.btn--sm` を 40px に下げている点を含む）。

優先度の付け方: **High** = 本番で目立つ／到達性に関わる、**Mid** = 世界観の統一、**Low** = 細部。

## 3. 「面白い実装」推奨 2 件

### A. 図版（Plate）シリーズ — オーナー写真の版画変換パイプライン（最優先）

**理由**: 「自分の写真の版画風変換」がオーナーに好評だった実績があり、方針（AI イラスト不採用）とも整合する。masthead の図版 I（T1）、今日の一葉の `story__figure`、詳細ページの上段、OG 画像まで同じ「図版」で貫くと、サイトの顔が一気に決まる。写真のない原種にも「図版未収録」ラベル（D1）が生きるので、**あるものと無いものの見せ方が一つの体系**になる。

**骨子**
1. **まず CSS だけの試作（30 分・要プレビュー）**: `archive.css` に `.plate--print img { filter: grayscale(1) contrast(1.4) brightness(1.05); mix-blend-mode: multiply }`、`.plate--print { background: var(--color-paper-2) }`。オーナーの写真 3 枚を `images/plates/` に置いて masthead と story で見比べる。これで「紙に刷った感」が足りるならパイプライン不要。
2. **本実装（1.5 日）**: 管理画面に「図版化」ボタンを追加し、ブラウザの `<canvas>` で変換（サーバー不要・CSP 内で完結）: グレースケール → 局所コントラスト（簡易 CLAHE または unsharp）→ 4 階調ポスタライズ → Floyd–Steinberg ディザ or 45° ハーフトーン → 白を透明・黒を `#1E2622` に着色 → WebP 1200px / 400px で `gallery-images/plates/<cultivar>.webp` に保存。`cultivar_images` に `is_plate boolean` を追加（または `cultivars.plate_path`）。
3. **表示**: `archive.js` に `plateUrl(displayName)` を追加し、`renderStory` / masthead（日替わりでローテーション、figcaption に `図版 XII — Anthurium crystallinum` のローマ数字採番）/ 詳細ページ D4 の左カラム / `og-image` エッジ関数の背景に使う。
4. **ルール**: 図版は必ずオーナー本人の写真から。投稿者写真を図版化する場合は投稿者の許諾フラグ（`cultivar_images.allow_plate`）を取ってから。

**コスト**: 試作 0.5h、本実装 1〜1.5 日、素材待ち（4 章）。

### B. 印刷用「標本ラベル」書き出し（print.css + ラベルビュー）

**理由**: `.specimen`（記載者・年・産地・採集者・両親）はすでに標本ラベルの情報構造を持っている。栽培者は実際に鉢へラベルを付けるので、「このサイトからラベルを印刷して鉢に刺す」体験は植物図鑑サイトにしかできない。印刷物として SNS に写り込むと、サイト本体の見た目を一切変えずに宣伝になる（本番プレビュー制約とも相性が良い）。

**骨子**
1. `css/print.css`（`media="print"`）: header / nav / gallery / actions / affiliate / footer を `display:none`、`.specimen` を 90×55mm のラベル枠（1px ink、内側に 0.5pt の二重罫）に整形、`h1.detail-title` を斜体セリフ、`.mono` の kicker に `AROID ORIGINS — plantsstory.com/anthurium/<epithet>`。`@page { size: A4; margin: 12mm }`、`.label-sheet { display: grid; grid-template-columns: repeat(2, 90mm); gap: 6mm }`。
2. 詳細ページの操作行（D2）に `ラベルを印刷` を追加 → `body.print-label` を付けて `window.print()`。同じ品種を 2〜4 枚並べるオプション（`data-copies`）。
3. QR はまず省略（URL を mono で印字）。必要になれば 3KB の QR 生成をインラインで持つ（外部 CDN は CSP で塞がれているので自前同梱）。
4. 実生の場合は `播種日 / 作出者 / 親` を載せ、投稿者名を入れる（有料機能「My Seedlings」の付加価値になる）。
