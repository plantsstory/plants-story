## 4. 優先順位（スマホでの効果順・12件）

1. **属一覧（不具合）**
   - 事実: 直接来ると「0 品種が登録されています」と出る。原因は `forms.js` 2092–2110 の件数の上書き。`pages.js` 1445 でデータを別に取りに行く経路では、この件数の行が更新されない。同じ経路だと並びも Clone と Hybrid が先になり、データが揃うと原種が先に変わる。
   - 直し方: この経路では `res.data.total` で件数の行を書き直す。並びはデータが揃った後と同じにする。
   - 効果: 検索から最初に来る属ページで、事実と違う数字が出なくなる。
2. **全体（件数）**
   - 事実: トップは40種、索引の区分の合計は41＋実生2、属ページは0、属の数字のチップは非表示。
   - 直し方: 「収録 = 必要項目が揃った件数」という1つの数え方で全画面を揃え、単位は「品種」にする。
   - 効果: 「どれが本当か」という迷いがなくなる。
3. **品種（重複した導線）**
   - 事実: 記録を追加する入口が3つある（操作の行、この台紙に書き足す →、不足項目の欄の「記録を追加する →」）。写真の下の注記と出口の行も重なっている。
   - 直し方: 操作の行の1つだけ残し、§3 の品種の項目を消す。
   - 効果: 1ページで約250px 短くなる。
4. **品種（タイトル周り）**
   - 事実: パンくず、`ANTHURIUM · 原種 · NO. 004`、タイトルの順に並ぶ。
   - 直し方: mono の行は区分のバッジだけにし、NO. は消す。
   - 効果: タイトルが上がり、1画面目に写真が半分見える。
5. **品種と一覧（信頼度の印）**
   - 事実: %、✓、出典 S、正確/疑問、検証済/未検証、収録済み、の6種類が出る。
   - 直し方:
     - 一覧は「% と ✓」だけにする。
     - 品種ページは「検証」の行1つにまとめ、ラベルではなく由来の記録の下へ移す。
     - S〜D の文字は用語集だけで説明する。
     - 検証の行の日付は1回だけにする。
   - 効果: 本文まで読まれやすくなる。Clone で「未検証」が最初に目に入らなくなる。
6. **トップ（長さ）**
   - 事実: 索引約1,200px と年表約950px が新着より上にある。
   - 直し方: 人物は5人まで、区分は消す、年表は閉じておく。並びは「今日の一葉 → 新着 → 索引 → 年表」にする。
   - 効果: 約1,500px 短くなり、毎日変わる区画が上に来る。
7. **全体（用語）**
   - 事実: 「収録」が7通り、「記録」が5通りの意味で使われ、台帳・台紙・目録・アーカイブも混在。
   - 直し方: §2 の表どおり `translations.json` の文言を置き換える。
   - 効果: 初めての人が言葉でつまずかなくなる。
8. **属一覧（行と操作）**
   - 事実: 一覧の前に操作の行が5段ある。各行に「由来: 1件」と頭文字の四角がある。
