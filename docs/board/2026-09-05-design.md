## 0. 総評 — 前回からの差分と、今回の判断軸

前回指摘の High はほぼ反映済み（44px、未収録シート、mono tier、紙色 theme-color、絵文字撤去、実生ノートの台帳化、並び順バーの縦積み、年表のリストのみ表示）。人物・産地・用語集・系統図・名前ビルダー・料金ページが加わり、**「読める図鑑」の骨格はできた**。

いま残っている問題は「旧デザインの残骸」ではなく、**機能の数そのもの**である。品種詳細 1 ページに、お気に入り・共有・編集・画像追加・削除依頼の 5 ボタン、写真ごとの Real/Fake 投票、記録ごとの 👍👎、Tier チップ、AI/IPNI/検証済バッジ、登録日、投稿者、広告枠、道具棚が載っている。収録 29 件・登録 6 人・写真 40 枚の規模で、これは「参加装置」が「記録」より目立つ状態。

判断軸は 1 つ: **その要素は「由来の記録」を読む・確かめる・書き足すのどれかに直接効くか。** 効かなければ削る（データは残し、UI だけ休止 = 可逆）。

### 2-2. データが薄いときの表示規則（例: AI 調査のみ、信頼度 23%）

trust 23 の AI 記録が持つのは、区分・作出者（多くは「不明」→ `clean()` で空）・補足 100〜200 字・出典 1 件（Tier C/D）だけ。このページでの規則:

1. **cite 行**は出せる要素だけ（年と国が無ければ非表示。空の「·」を出さない）。
2. **ラベル**は値のあるセルだけ（現状どおり）。加えて `trust <= 30` のとき `.specimen__note` に 1 行:
   `この記録は AI 調査のみ（信頼度 23%）。出典の確認・追記を歓迎します。`
3. **由来記録**は 1 件として普通に描く。見出し `記録 1 · AI 調査 · 信頼度 23% · 出典 C`。本文はそのまま。
4. 記録の直後に **不足リスト付きの未収録シート**（下記）。区分ごとの「あるべき項目」との差分を機械的に出す:
   - 原種: 記載者 / 発表年 / タイプ産地 / 採集者
   - Hybrid: 作出者 / 交配式 / 命名年
   - Clone: 命名者 / 命名年 / 由来（選抜元・交配式）
   - 実生: 交配式 / 播種日
5. **図版**が無ければ、ラベルの後に **図版未収録シート**（既存の `.gallery__empty-glass` を §2-3 の `.sheet` に統一。高さは 375px で 120px 以内）。
6. **関連**は前後リンクだけでも出す（`renderRelated` の `any` 判定は prev/next を含んでいるので現状で可）。
7. **道具棚**は文脈語が無いので非表示。
8. `ai_status` が pending / researching のときは 3〜4 の代わりに `.sheet--pending`。pending 由来（trust 0, `author.isAI`）は `renderOriginsInner` の冒頭で除外する（`origins.filter(o => !(o.trust === 0 && o.author && o.author.isAI))`）。

## 3. 次に作る「楽しい実装」— (b) 印刷用「標本ラベル」

### 選定理由（4 案の比較）

| 案 | 判断 | 理由 |
|---|---|---|
| (a) 図版シリーズ（CSS 版画処理） | **保留（素材待ち）** | 方針適合・効果大だが、オーナー写真 6〜10 枚（09-04 依頼）が未着。投稿者写真の図版化は許諾フラグが要る。素材が届けば CSS 試作 30 分で判断できるので、届き次第 (b) の後に着手。 |

### 実装の骨子（≤ 1 日）

1. **`wireframe/css/print.css`**（`<link media="print">`、約 120 行、3 時間）
   - `@page { size: A4; margin: 12mm }`。`body.is-label-print` のとき `header, .mobile-nav, .breadcrumb, .detail-actions, .gallery-carousel, #origins-container, #add-origin-section, .related, .affiliate-section, .footer { display: none }`。
