# デザイン・UX — 投稿と「あとから足す」をアプリの使い心地に

- 日付: 2026-10-08／担当: 常設ボード デザイン・UX
- オーナーの依頼（原文）: 「投稿とその後の画像やその他追加がしやすいようにしてほしい。できればアプリみたいな使い心地にしたい。ちかづけたい」
- 前提: 利用者の大半はスマホ（375px）。第7回の決まり（UNIFIED LAYER、文字 6 段、ボタン 3 種＋切替 1、四辺の枠 5 つ＋系統図）を守ります。絵文字・影・グラデーションは使いません。送り先の RPC と引数は変えません。
- 方法:
  - 本番 https://plantsstory.com を headless Chrome で 375×812 に描画し、タッチ端末を再現して（`TOUCH=1`）、未ログインで操作しました。
  - 対象は、品種ページ（写真あり crystallinum／写真なし hookeri）と投稿フォーム（4 区分）です。計測スクリプトは scratchpad の `ux\detail.js`・`ux\contrib.js`、画像は `ux\*.png` です。
  - **ログインした状態の手順は、コードを読んで数えました。** 本番にテストの投稿や写真を残さないためです。

## 0. 要約

**いま「追加しにくい」原因は、手順の長さより「失敗が見えないこと」と「途中で消えること」です。**

1. **写真**
   - ログインしていないと、写真を選んで質問ダイアログ（`prompt()`）2 つに答えても、何も起きません。アップロードに失敗すると端末の localStorage に退避し、画面には出さず、知らせもしません。
   - ログインしていても、送信中・完了の表示がありません。
   - 実生のページには「写真を追加」自体が出ません。
2. **記録**
   - ログインしていなくても書けてしまいます。送ると「由来が追加されました！」と出たあと「DB保存に失敗しました」になり、本文は消えます。
   - 「項目を分けて書く」を開いても中身が空です。
3. **新しい品種の投稿**
   - フォームの高さは 2,277〜2,623px（3 画面強）あります。区分（原種・Clone など）を選ぶ欄が名前の欄より下にあるため、選んだあとに上へ戻る必要があります。
   - ログインの確認は送信を押したときに初めて出ます。ログインすると Google の画面へ移るので、入力した内容と写真がすべて消えます。下書きの保存はありません。
4. **ホーム画面に追加**
   - アイコンの PNG（192px とアップル用 180px）が 2 つとも壊れています。Chrome で表示すると、192 は何も描かれず、180 は下半分が崩れます。
   - 原因は `.gitattributes` がなく、`core.autocrlf=true` で改行コードを変換されたためと推定します。
   - 静的ページ（品種・人物・産地）の `manifest.json` とアイコンの参照が相対パスで、本番では 404 です。

**「アプリみたい」は、次の 4 つで作ります。**
- 下部の帳面バー（≤640px。図鑑・一覧・＋投稿・自分の記録・その他）
- 写真を載せるシート（`prompt()` をやめ、プレビュー・撮影日・送信中・完了を出す）
- 投稿の 5 手順化（区分 → 名前 → 由来 → 写真 → 確認。最後に自分の標本ラベルの仕上がりを見せる）
- 「自分の記録」画面（自分の品種に、1 行から写真を撮って足せる）

ログインは「最初に 1 回」にし、下書きは自動で残します。

**作らないもの**: 浮動ボタン、自前のカメラ、トリミング、プルで更新、オフライン閲覧、送信の予約、通知。理由は §3 に書きます。

## 1. いまの手順（実測・375px）

### 1-1 手順ごとのタップ数

タップ数は、入力欄に触れる回数を含み、文字を打つ動作は数えません。

| 手順 | ログイン済み | 初めての人（未ログイン） |
|---|---|---|
| **A. 新しい品種を投稿**（Clone・写真 1 枚・トップから） | 約 17 タップ。スクロール約 3,000px（うち上へ戻る約 600px）。「+ 投稿」→ 属の選択に 2 タップ（直接開くと未選択）→ 区分（y=1,094）で Clone → 名前の欄（y≈700）へ戻ってクローン名 → 画像（y≈1,340）→ 端末の選択・写真 → 名付けた人物・年・交配式 A・B → 投稿する（y≈2,400） | 上の手順に、ログインの 3〜4 タップが加わります。ログインせずに書き終えると、送信時に「投稿するにはログインが必要です」（3 秒で消える）と出て、ログインの欄（y=227）まで約 2,200px 戻ることになります。Google へ移るので、**入力も写真も消えます** |
| **B. 写真を追加**（品種ページから） | 5 タップ: 写真を追加（y=493、1 画面目）→ 端末の選択 → 写真 → `prompt`「補足」OK → `prompt`「リンクURL」OK。送信中と完了の表示はありません。1 枚ずつです | 同じ 5 タップのあと、**何も起きません**。アップロードは拒否され、localStorage に退避して、画面には出しません（`forms.js` 2551〜2585 付近） |
| **C. 記録を追加** | 5 タップ: 記録を追加 → 本文 → 出典 URL → ＋追加 → 投稿する。押すとページが約 940px 下へ飛び、フォームの見出しが固定ヘッダー（57px）の下に隠れます。「項目を分けて書く」は開いても空です | 書いて送ると「由来が追加されました！」→「DB保存に失敗しました」と出て、本文は消えます |
| **D. 個体を追加**（原種のページから） | 5 タップ: その他 → 個体を追加 → 番号 → 年 → 個体を登録。写真を載せるには、新しいページでさらに B の 5 タップが要ります | 登録を押した時点でログインを求められます。ログインから戻ると個体用のフォームではなく、通常の投稿フォームになります |
| **E. 自分の実生に成長写真を足す** | 実生のページには「写真を追加」が出ません（`pages.js` 1354 付近）。≡ → 投稿履歴 → カード → その他 → 編集 → 約 2,600px のフォームで画像まで下りる → 選ぶ → 投稿する。**約 10 タップとスクロール約 2,000px** | — |

### 1-2 そのほか測った値

- **投稿フォームの高さ**: 原種 2,623px（入力欄 16）・Hybrid 2,277px（13）・Clone 2,421px（15）。実生は、未ログインでは選ぶと原種に戻されるため測れません。
- **区分による名前欄の変化**: Clone を選ぶと名前の欄が 380px から 254px に縮み、その下が 126px ずれます。
- **画像の欄**: 「ドラッグ&ドロップ または クリック」はスマホに合わない文言です。「最大3枚」と書いてありますが、コードの上限は 10 枚です（`upload_error_max`）。
- **品種ページの操作行**: 2 行・94px（共有・写真を追加・記録を追加／その他）です。その他の中身は、個体を追加・ラベルを印刷・再調査を依頼・報告です。
- **ヘッダー**: 固定で 57px あり、スマホでは「+ 投稿」と ≡ だけが出ます。ログインは ≡ の中にしかありません。
- **ホーム画面まわり**:
  - manifest: `start_url "./index.html"`。id・scope・shortcuts がありません。説明文は旧文（「コミュニティで収集・共有するプラットフォーム」）です。
  - アイコン: 512px は SVG だけで、maskable も同じ SVG です。配色は旧 HEX（#1B4332 / #52B788）です。
  - インストール案内: 30 秒後に全ページで出ます。影があり、「オフラインでも利用可能」と事実と違うことを書いています。
  - `offline.html`: 旧デザイン（濃緑のグラデーション・緑のボタン・角丸 8px）のままです。

## 3. 「アプリみたい」を具体的にする — やること・やらないこと

| 項目 | 判断 | 理由・中身 |
|---|---|---|
| ホーム画面に追加（PWA） | **やる** | アイコンを作り直し、manifest に id `/`・scope `/`・start_url `/`・standalone・shortcuts（投稿する／自分の記録／Anthurium の一覧）を入れる。iOS 用に `apple-mobile-web-app-title` を足す。参照はすべて `/` から始まる絶対パスにする。ホーム画面から開いたかどうかは、GA に `display-mode` で送る |
| インストールの案内 | **形を変えてやる** | 30 秒後のバナーはやめる。最初の投稿が終わったあとと「自分の記録」に、1 行だけ出す。Android は端末の追加画面を呼ぶ。iPhone の Safari には「共有 → ホーム画面に追加」と文字で案内する。「オフラインでも」とは書かない |
| 下部のタブバー | **やる（≤640px だけ）** | 5 項目を文字で出す（図鑑・一覧・＋投稿・自分の記録・その他）。どこを読んでいても、親指の位置から「足す」に届くようにする。アイコンだけのボタンは決まりで禁止なので、文字だけにする |
| 浮動ボタン（右下の丸い＋） | **やらない** | 影が前提の部品で、本文の上に重なる。Material 風に見え、「AI っぽさ」の典型 |
| 画面の切り替え | **控えめにやる** | ページ間は 120ms のクロスフェード（View Transitions。対応しない端末は今のまま）、シートは下から 180ms。`prefers-reduced-motion` のときは 0 |
| 投稿の段階化 | **やる（新しい品種の投稿だけ）** | 5 手順にして、各手順を 1 画面に収める。記録の追加と個体はもともと短いので、1 画面のままにする |
| カメラから直接撮る | **やる（端末のカメラを使う）** | 「写真を追加」は端末の選択画面を開く（iPhone も Android も、その中に「撮る」がある）。「自分の記録」の「撮る」は `capture="environment"` でカメラを直接開く |
| 自前のカメラ画面（getUserMedia） | **やらない** | 端末のカメラのほうが良い。許可のダイアログが増え、作る手間も大きい |
| トリミング・回転・フィルタ | **やらない** | 写真はトリミングしない決まり（第7回 §5） |
| 下書きの自動保存 | **やる（文字だけ）** | 入力のたびに localStorage へ残し、ログインの往復や誤操作で消えないようにする。写真は残さない。代わりにログインを最初に済ませるので、写真を選んだあとに消えることはなくなる |
| 送信後の戻り先 | **決める** | 新しい品種はその品種のページへ（今と同じ。共有の帯を出す）。写真が 0 枚なら「写真を追加」の帯も出す。写真は同じページの新しい図へ。記録は同じ位置の新しい記録へ。個体は新しい個体のページへ移り、写真シートを出す |
| 成功の知らせ方 | **やる（知らせの行）** | 結果が見える場所へ連れていき、下に 1 行だけ出す。影なし。失敗の知らせは閉じるまで残し、「もう一度」を付ける |
| 読み込み中の骨組み | **既決（第8回 I1）を続ける** | 新しく足すのは「送信中の写真」の骨組みだけ（台紙の枠に「送信中」の 1 行）。「自分の記録」の行の骨組みも一覧の行の形にそろえる |
| プルで更新 | **やらない** | ブラウザで開いているときは、ブラウザ側に元からある。ホーム画面から開いた iPhone には無いが、データの変化は遅い。代わりに、30 分以上離れて戻ったら静かに取り直す |
| オフライン | **正直な表示だけやる** | 電波がないときは「電波がありません — もう一度」のシートを出し、送信ボタンは「電波が戻ったら送れます」にする（入力は下書きに残る）。`offline.html` を Field Archive の見た目にする |
| オフライン閲覧・送信の予約（Background Sync） | **やらない** | iPhone が対応していない。読み込み中の静的ページは 8 秒で消える仕組みなので、オフラインで読めるとは約束できない |
| プッシュ通知 | **やらない** | iPhone はホーム画面への追加と許可が要る。お知らせはオーナーの承認制。AI 調査が終わったことは「自分の記録」に印を付けて伝える |
| 端末の「共有」から写真を受け取る（share_target） | **今はやらない（条件付きの 12 番）** | Android だけの機能で 1 日かかる。ホーム画面から開く Android の利用者が多いと分かってから |
| 振動 | **やらない** | iPhone は非対応で、効果も小さい |

## 4. 設計

### 4-1 下部の帳面バー（≤640px）

- **置き場所**: `index.html` の `</main>` の直後に `<nav class="appbar" aria-label="下部ナビ">` を置きます。新しい JS ファイルは作らず（キャッシュバスター 12 箇所を増やさないため）、処理は `archive.js` に足します。
- **項目**: 次の 5 つで、それぞれ幅 20%・高さ 52px＋`env(safe-area-inset-bottom)` です。
  - 図鑑（`data-nav="top"`）
  - 一覧（`data-nav="genus" data-genus="anthurium"`）
  - **＋投稿**（`#appbar-post`）
  - 自分の記録（`data-nav="mypost"`）
  - その他（`#mobileNav` を開く）
- **見た目**（決まりの「切替」を使います）:
  - 文字はゴシック `--fs-label`、色は mid です。選んでいる項目は ink にし、上に 2px の ink 線を引きます。
  - 「＋投稿」だけは主ボタン（ink 塗り・紙色の文字・500）です。ヘッダーの「+ 投稿」の例外を、ここへ移します。
  - バーの上辺は 1px `--color-rule-strong` で、地は紙色です。影は付けません。
- **ヘッダー（≤640px）**:
  - 固定をやめ、ロゴだけにします（「+ 投稿」と ≡ はバーへ移ります）。
  - ホーム画面から開いたときは、ロゴの左に「← 戻る」を出します（§4-9）。
  - **裁定事項です**（§6）。
- **隠すとき**:
  - 投稿の手順の画面では、手順の下部バーと入れ替えて隠します。
  - キーボードが出ているとき（`visualViewport.height` が `innerHeight` の 75% 未満）も隠します。
  - `body` の下の余白はバーの高さ分取り、知らせの行は「バーの上＋12px」に出します。
- **「＋投稿」の動き**:
  - 品種ページでは、シート（§4-2）を出します。
  - それ以外のページでは、投稿の手順 1 へ直接移ります。
  - 未ログインなら、ログインのシート（§4-7）を先に出します。

### 4-2 「＋投稿」シート（品種ページ）

- 既存の `.dialog-clean` を、画面の下からの形にした `<dialog class="dialog-clean sheet-dialog">` を使います。
- 後ろの幕は ink 35% の 1 色にします（影でもグラデーションでもない、という扱い）。Chrome 120 以降の Android では、戻るボタンで閉じます。
- **中身**:
  - 1 行目: 標題行（`ANTHURIUM · 原種 · NO. 035`）と品種名（見出し3・学名はイタリック）
  - 行（44px・細罫）: **写真を追加 →**／**記録を追加 →**／個体を追加 →（原種だけ）
  - 太罫 1 本のあと: 新しい品種を登録 →／実生を記録 →
- 「写真を追加」の行を押すと、その押す操作の中で `gallery-file-input.click()` を呼びます。端末の選択画面が開くのは、ユーザーが押した操作の中だけだからです。

### 4-3 写真を載せるシート（`prompt()` 2 回の置き換え）

- **入口**: 次の 3 つから、同じ関数 `openPhotoSheet(cultivarName, files)` を呼びます。h1 から名前を読まないので、ページの外からも使えます。
  - 品種ページの操作行
  - 未収録シートの「写真を追加」
  - 「自分の記録」の行
- **選ぶ欄**:
  - `accept="image/*"` と `multiple` にし、一度に 3 枚までにします。「撮る」だけ `capture="environment"` を付けます。
  - 形式のチェック（`validateFile`）は MIME の一覧で弾かず、実際に画像として読めるかで判断します。iPhone の HEIC も、Safari が読めればそのまま通ります。
- **シートの中身**:
  - 台紙の枠（四辺の枠 #2）に写真を `contain` で並べます。
  - 撮影日: 写真の EXIF に撮影日時（DateTimeOriginal）があれば入れます。**なければ空欄のままで、今日の日付は入れません**（推測を書かない方針）。
  - 補足（1 行。例「栽培株 · 温室で 2 年目」）と、`<details>` の中のリンク（Instagram など）
  - 小さな文字で「自分で撮った写真だけを載せてください。撮影者 {プロフィール名} として載ります。」
  - 主ボタン「載せる」と、テキストリンク「やめる」

### 4-9 PWA の作り直し

1. **アイコン**: 紙色の地（#F4F1EA）に ink 1 色です。案は 2 つで、オーナーが選びます（§7）。

2. **`.gitattributes`**: 次の内容にして、壊れたファイルを入れ直します。

   - `*.png binary`、`*.jpg binary`、`*.webp binary`、`*.ico binary`、`*.woff2 binary`、`*.pdf binary`
3. **PNG の検査**: デプロイのたびに走る自動チェック（T103。管理画面に結果を出し、デプロイは止めない）に、「リポジトリの PNG がすべて読めるか」を足します。今回 Chrome で崩れて表示されたのはアイコン 2 点です。
4. **manifest.json**: 次の値にします。

   - `shortcuts` は 3 つ: 投稿する `/contribute`、自分の記録 `/mypost`、Anthurium の一覧 `/anthurium/`
5. **head**: `index.html` と静的ページのジェネレーター（`scripts/generate-static-pages.js`）の両方で、次のようにします。
   - `/manifest.json` と `/icons/apple-touch-icon-180.png` を絶対パスにする
   - `<meta name="apple-mobile-web-app-title" content="Aroid Origins">` と `<meta name="mobile-web-app-capable" content="yes">` を足す
6. **ホーム画面から開いたときの「戻る」**:
   - `matchMedia('(display-mode: standalone)')` が真で、SPA の中で 1 回以上移動していれば、ヘッダーに「← 戻る」（テキストリンク・44px）を出し、`history.back()` を呼びます。
   - GA に `display_mode` を送ります。
7. **オフライン**:
   - `offline.html` を紙・ink・`.sheet` の点線にし、文言は「電波がありません」「電波が戻ったら、もう一度開いてください」と主ボタン「もう一度」にします。
   - SPA の中でデータの取得に失敗したときは、「読み込み中…」のまま止めず、同じシートを出します。
8. `sw.js` の `ASSET_VERSION` とキャッシュバスター 12 箇所を更新します（いつもの手順）。
